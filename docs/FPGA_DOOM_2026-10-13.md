## Failure evidence

Captured screen: `frame-001.png`, native 720×400 text scan-out, CRC32
`e9a7bc51`. A later independent capture has the same pixel CRC. It shows
FreeDOS startup, `DOOM_DEMO3_START`, an invalid-opcode report and return to DOS.

The printed words are **IP, CS, FLAGS**, not CS:IP:
`6263 244C 0246`. FreeDOS prints the exception stack in order; see its
[handler](https://github.com/FDOS/kernel/blob/master/kernel/entry.asm).
The corresponding physical address is `0x244C0 + 0x6263 = 0x2A723`.
Read-only guest-RAM capture contains:

```text
2a71f: 8b 26 da 0c       mov sp,[0x0cda]
2a723: 0f 01 26 88 0f    smsw word [0x0f88]
2a728: e8 be d5          call ...
```

This complete byte sequence matches the original DOOM.EXE at file offset
`0x802F`; no guest code was replaced. The frozen image's `decode_stages.sv`
hash is `bd01c3a8dc5d9b2d456e1a974fdfab5679808d0e617261ed4cba72642f113e3f`,
matching the implementation input ledger. Its lines 537–554 accept register
SMSW only and send memory SMSW to `d_unknown`. The current checkout still
contains that explicit limitation. The RAM dump is post-fault evidence, not
a first-fault architectural snapshot.

The initial launch used the newer posted-write-safe daemon by mistake. It
correctly refused the older image's absent posted-DDR capability **before RAM
initialization**, exit 1. Its receipt is retained. The second launch uses the
previously qualified daemon matched to this image, without weakening a guard.

## Proposed general fix

Implement `0F 01 /4` memory SMSW as an ordinary **16-bit store**, including
32-bit operand-size prefixes, through the existing segment/paging/fragment
machinery. Preserve register SMSW semantics and unprivileged access; do not
route the memory form through privileged MOV-CR checks. Add QEMU-differential
tests for real/protected/V86 modes, CPLs, address-size/prefix variations,
unaligned/page-straddling stores and precise segment/page faults, plus unchanged
register-form controls. Update opcode coverage. Then rerun the standard suite
and Doom on new hardware. **No implementation change is part of this test.**

Follow-up: [isolated SMSW repair and microtests](../verif/sys/smsw_memory/README.md).
The first 80 cold-boot memory-form probes reproduce the exact #UD on pre-fix
RTL; eight ordinary-store controls pass both. The isolated three-file repair
and its subsequent composition with the timing candidate each pass **248
complete-trace QEMU differential case executions**: 88 initial probes/controls,
60 CPL3/V86, 25 paging, and 75 fault-repair/retry cases at AXI latencies 0/7/31.
The composition reruns the same corpus; it does not add 248 unique fixtures.
Twenty LOCK/segment-denial cases satisfy Intel-spec RTL self-checks but diverge
from the permissive pinned QEMU, so that fault driver remains red. The combined
candidate's canonical gate also remains **7 PASS / 101 FAIL**; exact same-input
parent/candidate replay is not a substitute for a green differential gate.
The isolated repair also rejects all 125 fault-test negative variants; that
negative-control result has not been repeated on the composition.

Broader fault corners, full-PC and standard-suite qualification, synthesis and
physical FPGA validation remain open. The repair is **not promoted or
programmed**. These simulation results do not change the failed physical Doom
result: the existing bitstream and original Doom executable remain unchanged,
