# FPGA Doom timedemo — 2026-10-17

**PASS: original DOS Doom shareware 1.9 completes DEMO3 at 20.50 FPS** on the
physical RK-XCZU15EG-F, measured **39.999830 MHz**, with **U/V + fast-pipe**.
This was a cold FreeDOS boot on the existing `2886d24c` image: no rebuild,
reprogramming, clock change, snapshot, guest patch, STEP or breakpoint.
It supersedes the [old image's startup failure](https://github.com/AL-255/ventium/blob/a4456e81/docs/FPGA_DOOM_2026-10-13.md), not
by substituting a slow/U-only control.

The fresh, closed `DOOM/DEMO3.LOG` reports:

```text
timed 2134 gametics in 3644 realtics
```

The original WAD's embedded DEMO3 independently contains exactly **2,134
single-player tics**. At 35 realtics/second, this is **104.114286 seconds** and
`35 × 2134 / 3644 = 20.496707 FPS`. This is rendered timedemo throughput,
not capture cadence or a higher-clock projection. See id Software's
[timedemo result path](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/g_game.c)
and [35 Hz tick definition](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/doomdef.h).
The normal timedemo result is intentionally emitted through Doom's `I_Error`
exit path; that result line is not a processor failure. The log's missing
external `DEMO3.lmp` notice is followed by playback of the embedded WAD demo.

## Workload and execution evidence

```text
DOOM -CONFIG BENCH.CFG -NOSOUND -TIMEDEMO DEMO3 > DEMO3.LOG
```

- **320×200, high detail**, `screenblocks 10` (full-width view with status bar),
  `usegamma 0`; sound disabled. Original executable/WAD hashes match before
  and after execution. Benchmark configuration and AUTOEXEC are unchanged.
- Passive captures show gameplay at 40, 80 and 120 seconds, followed by
  `DOOM_DEMO3_RETURNED` and the DOS prompt at 180 seconds. No visible error.
  Sixteen CRC-checked screenshots are retained, with original RGB332 colors;
  this run did **not** record a continuous movie.
- Both the owned native daemon and controller exit **0**, naturally, with no
  timeout, forced stop, debugger freeze or cleanup error. The disk is graded
  only after daemon exit; the original input contains **no DEMO3.LOG**.
- All **200 frozen source pins** match. The retained **159 defines** include
  `VEN_SYS_FASTPATH`, `VEN_SYS_FASTPATH_RELOC`, `VEN_SYS_FASTLOAD_FLAT`,
  `VEN_SYS_FASTLOAD_BOUNDED`, `VEN_SYS_FASTSTORE_FLAT` and `VEN_FE_PIPE`;
  the frozen shim connects `.cycle_mode(1'b1)`.
- Fresh run-wide counters prove at least **541,529,155 V retirements**:
  5,119,730,384 total U+V events minus at most 4,578,201,229 primary/U events.
  Each counter is baselined separately because primary/U survives guest reset
  while U+V does not. Both possible V-valid assertions in the pinned source
  reside in `core_fastpath.svh`'s S_PIPE path, proving actual fast pairing.
  These counts include boot and the idle DOS prompt, and count REP elements;
  **they are not a Doom gameplay IPC measurement**.

Current verified **Quake** gameplay IPC remains **0.496499864 total U+V** on
this same image, cycles **625,021,130,428–629,480,208,865**; primary/U alone is
0.383002768. See the [completed Quake run](FPGA_QUAKE_TIMEDEMO_2026-10-17.md).
Doom gameplay IPC is unmeasured, not substituted with that Quake number.
